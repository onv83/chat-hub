# Mattermost unread contract

`tests/polling.mjs` executes the actual JavaScript generated by `mmLastPosts` and
`mmTabCounts` in an isolated VM with synthetic HTTP responses. No account, browser
session, mark-read operation or application restart is used.

## Primary references checked

- Official API: https://docs.mattermost.com/api/reference/get-channel-unread
- OpenAPI source: https://github.com/mattermost/mattermost/blob/master/api/v4/source/channels.yaml
- Response model: https://github.com/mattermost/mattermost/blob/master/server/public/model/channel_member.go
- Server calculation (`GetChannelUnread`): https://github.com/mattermost/mattermost/blob/master/server/channels/store/sqlstore/channel_store.go
- Team aggregation (`GetTeamsUnreadForUser`): https://github.com/mattermost/mattermost/blob/master/server/channels/app/team.go
- Actual DM/group sidebar routes: `webapp/channels/src/components/sidebar/sidebar_channel/sidebar_direct_channel/sidebar_direct_channel.tsx` and `sidebar_group_channel/sidebar_group_channel.tsx` in the same upstream repository.

## Contract

- Resolve `/api/v4/users/me`, then address that explicit user ID. Recheck the
  account before publishing the batch. Do not reuse username resolution from a
  previous account or an earlier username assignment.
- `GET /api/v4/users/{user_id}/channels` lists memberships across teams, including
  teamless D/G channels. This endpoint requires Mattermost **6.1+**. Failure is
  unknown; there is no unsupported posts/member fallback.
- O/P routes are `/{team_name}/channels/{channel_name}`. Match the exact team ID
  resolved from its name, not the first channel with that slug.
- D routes are `/{team_name}/messages/@{username}`. Resolve the username and match
  the sorted exact pair of current-user and peer IDs in the D channel name.
- G routes are `/{team_name}/messages/{channel_name}` (**not channel ID**).
  D/G membership and identity are account-wide, not team-scoped.
- Reject a pin from another origin, ambiguous matches, unsupported paths and
  unresolved teams. Deduplicate channels by ID and reuse one snapshot for aliases.
- `GET /api/v4/users/{user_id}/channels/{channel_id}/unread` has **no query
  parameters**. Its `msg_count` and `mention_count` are the authoritative total
  unread fields. `msg_count_root` and `mention_count_root` are separate root-only
  values; preserve them separately, never add them to total fields. This is not
  an implementation of the Mattermost collapsed-thread inbox UI.
- The server computes total unread from channel/member counters; a member's
  `msg_count` by itself is a read position. Do not count modified posts returned
  by a `since` query and do not attempt to subtract own/edited posts locally.
- HTTP errors, invalid JSON, mismatched channel/team IDs, missing fields and
  invalid counts preserve previous count/observation time. A successful zero is
  distinct from unknown. Partial batches publish only verified channels.
- The existing service-tab endpoint `/users/me/teams/unread` remains in use;
  validate every returned team before summing. Its totals follow the server's
  notification/mark-unread settings; they are not an unconditional sum of pinned
  channels. Do not add root or thread fields to its total fields.

## Verification boundaries

All existing single-flight, physical guest-call slots, deadlines, generation
checks and priority read probes remain in place. Regression tests cover hung
calls, superseded results, service independence and a targeted real guest probe.
The targeted probe skips preview fetching and performs only GETs.

No live deployment, server-version compatibility, latency or account unread
transition was tested. Unsupported permalinks, routes without a team segment and
subpath-hosted routes fail closed rather than guessing channel identity.
