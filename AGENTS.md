# AGENTS.md — правила для тех, кто правит этот репозиторий

## 1. Сначала найти готовое, потом писать

Перед любой новой функцией для мессенджера:

1. Прочитать `C:\Users\Lenovo\chat-hub-coordination\MCP-REUSE-MAP.md` — карта готовых модулей с путями и строками.
2. Проверить репозиторий и коннекторы:
   ```bash
   grep -rn "нужный_селектор\|имя_функции" C:/Users/Lenovo/mcp/*/src C:/Users/Lenovo/chat-hub/renderer.js
   ```
3. Если готовое найдено — порт 1:1 из `файл:строки`. Переписывать отлаженный механизм заново запрещено: это повторная оплата уже сделанной работы.

Пример: переключение чатов MAX уже реализовано — `mcp/max-mcp-b22-runtime/src/max_user_history_mcp/live_browser.py:117-133` (`button.cell`, `h3.title .name .text`) и `:345-360` (ожидание заголовка 25×200 мс). Не изобретать клик по `aside div.item` и не ждать смены `location.pathname`.

## 2. Записывать каждую правку

Любое изменение модулей мессенджеров — запись в `CHANGELOG-MESSENGERS.md`: дата, сервис, что изменено, почему, какими тестами закрыто. Без записи пакет не принимается.

## 3. Не ломать живой профиль

- Не читать `%APPDATA%\ChatHub\config.json` сторонними скриптами при работающем ChatHub: Python-чтение без `FILE_SHARE_DELETE` блокирует атомарную замену, сохранение настроек падает с `EPERM`.
- Тесты — только на фикстурах; живые переписки не вычитывать.
- Перенос в живой корень — только после полного `npm test` и `npm run test:ui` с зафиксированными числами и с бэкапом.

## 4. Где что лежит

- Мост и ядро экспорта — `mcp-export/` (CommonJS, без внешних зависимостей).
- Экстракторы сервисов и UI — `renderer.js`; IPC и запуск моста — `main.js`.
- Реестр коннекторов — `%LOCALAPPDATA%\ChatHub\mcp\connectors.json` (пути только внутри `C:\Users\Lenovo\mcp` и этого каталога).
- Карта готового и команды поиска — `chat-hub-coordination\MCP-REUSE-MAP.md`.
